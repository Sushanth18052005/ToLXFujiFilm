# Workshop QR Entry System

Import registrations from Excel, email every attendee a unique QR code, and
verify entry at the door from any phone. Each QR checks a person in exactly
once — a second scan shows **Already Entered** and denies entry.

## How it works

1. **Import** the registration spreadsheet → each person gets a random,
   unguessable token stored in a shared Postgres (Neon) database.
2. **Email** each attendee their personal QR code (the QR encodes
   `BASE_URL/scan?t=<token>`), from the `/admin` page or the `npm run send` CLI.
3. At the entrance, staff open `/scan`, log in once, and point a phone camera
   at each QR. Valid codes are marked **Entered**; repeats are rejected.

The token is a 24-byte cryptographic random value — it is not derived from any
registration field, so it can't be guessed or forged. Marking entry is gated
behind a shared staff password, and the check-in write is atomic, so two
simultaneous scans of the same code can never both succeed.

Because the database is hosted (Neon), your machine and the deployed server share
the exact same attendees and tokens — there is no seed file to ship, and entry
status is durable across restarts and redeploys.

## Setup

```bash
npm install
cp .env.example .env      # then edit .env (see below)
npm run init-db           # create the tables in your Neon database (idempotent)
```

Edit `.env`:

- `DATABASE_URL` — your Neon (Postgres) pooled connection string. Keep it secret.
- `BASE_URL` — the public HTTPS URL of the deployed site. **Must be HTTPS** or
  phone cameras will refuse to open the scan link and refuse camera access.
- `STAFF_PASSWORD` — what staff type to unlock the scanner.
- `SESSION_SECRET` — a long random string (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`).
- `BREVO_API_KEY` / `MAIL_FROM` — email is sent via Brevo's transactional HTTP API
  (Render's free tier blocks outbound SMTP, so Gmail/SMTP won't work when hosted).
  Create a free Brevo account, verify a sender, generate a **REST** API key
  (`xkeysib-…`), and set `MAIL_FROM` to that verified address.

## Usage

```bash
npm run import -- ./data/registrations.xlsx   # load the spreadsheet into Neon
npm run send                                   # email un-emailed attendees their QR
npm run send -- --dry-run                      # preview who would be emailed
npm run send -- --resend                       # email everyone again
npm run start                                  # run the entrance web app
```

The importer auto-detects a **Name** column and an **Email** column (any header
containing "name" / "email"). Every other column is preserved and shown to
staff on scan. Re-running the import updates existing people and keeps their
tokens (matched by email, or by name when there's no email).

## At the door

- `/scan` — live camera scanner (continuous). Green = entered, red = already
  entered / denied.
- `/admin` — live counts, search, add/delete attendees, **Undo** an accidental
  check-in, and **email QR passes** (with a live progress bar).

Staff can also just use their phone's native camera: scanning the QR opens the
scan URL directly, which verifies the code after a one-time staff login.

QR images are generated on demand and served at `/qr/<token>.png` — the same URL
the emails embed — so there are no PNG files to generate or store.

## Deploying to Render (free tier)

The database lives in Neon, not on Render, so the free plan is enough: entry
status is durable, and there's no persistent disk to pay for.

1. Push this repo to GitHub, then in Render: **New + → Blueprint** and point it at
   the repo. `render.yaml` provisions a free Node web service.
2. Set the `sync: false` env vars in the dashboard: `DATABASE_URL` (the same Neon
   string as local), `STAFF_PASSWORD`, `EVENT_NAME`, `BREVO_API_KEY`, `MAIL_FROM`,
   and (after the first deploy gives you a URL) `BASE_URL` = `https://<name>.onrender.com`.
   `SESSION_SECRET` is generated by Render automatically.
3. Redeploy after setting `BASE_URL`. Because both machines point at the same Neon
   DB, the QRs you email verify correctly at the door.

Notes:

- Email sends leave from **Render's** outbound IP, not your laptop. If you use
  Brevo's *Authorised IPs* security feature, disable it or allowlist Render's
  outbound IPs (dashboard → your service → **Connect → Outbound**), or sends 401.
- The free service sleeps after ~15 min idle, so the first scan/request after a
  quiet spell waits a few seconds for a cold start. Entry data is safe in Neon.
- Run a single instance; the background email job is tracked in memory per instance.

| Path | Purpose |
|------|---------|
| `scripts/make-template.js` | Writes a blank registration template |
